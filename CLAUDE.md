# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

AutoCAD MCP Pro is a FastMCP 3.0 server that exposes about two hundred and forty tools, a dozen resources, and five prompt templates for producing AutoCAD drawings. (The exact tool count is reported dynamically by `system_status` / `system_about` — never hardcode it.) This fork (`FORK.md`) is **headless only**: one engine, ezdxf, works anywhere without AutoCAD; DWG is read and written through the ODA File Converter. The upstream live AutoCAD (COM) engine and the tools that needed it were removed (`CHANGELOG.md`, *Unreleased*).

## Running the Server

```bash
# STDIO mode (default, for MCP clients like Claude Desktop)
python server.py

# HTTP mode
fastmcp run server.py:mcp --transport http --port 8000
```

`AUTOCAD_MCP_BACKEND` accepts `auto` (default) and `ezdxf`; any other value, `com` included, fails startup.

## Installation

```bash
# Core
pip install -e .

# With PDF/screenshot support via matplotlib
pip install -e ".[pdf]"

# XLSX workbooks (takeoffs, data_extract) via openpyxl
pip install -e ".[office]"

# Everything
pip install -e ".[full]"
```

## Running Tests

```bash
pytest
pytest tests/test_specific.py::test_name   # single test
pytest -x                                   # stop on first failure
```

Uses `pytest-asyncio` for async test support.

## Architecture

### Backend

- `backends/contracts/` — the interface, one module per domain (`drawing.py`, `layouts.py`, `entity_creation.py`, …). Split in v1.5.0 out of a single 1854-line ABC; some slices (premium, gdt, settings) also carry shared *concrete* implementations, so they are mixins rather than pure interfaces.
- `backends/capability.py` — the refusal vocabulary (`UnsupportedCapabilityError`) plus `@capability(key, reason=...)`, which marks a contract method optional and gives it a default that **raises** that refusal. Use it only for genuine engine boundaries, never for an unfinished method; `@abstractmethod` stays the default. Every key used must be declared in the engine's capability map (`EzdxfBackend.capabilities()`) — `tests/test_capability_contract.py` fails otherwise, which is what stops the decorator becoming a way to ship undeclared holes.
- `backends/base.py` — shared dataclasses (`EntityInfo`, `LayerInfo`, `BlockInfo`, `DrawingInfo`, `CapabilityMap`) and the `AutoCADBackend` composition of every contract. `from backends.base import AutoCADBackend, UnsupportedCapabilityError` works.
- `backends/ezdxf_backend.py` — `EzdxfBackend`: file-based DXF operations using the `ezdxf` library. All sync ezdxf calls are wrapped with `asyncio.to_thread` via `_async()`. Transactions are implemented as full DXF snapshots on an `_undo_stack`.
- `server.py::_make_backend` always builds `EzdxfBackend` (after `_check_backend_setting`).
- `backends/session_backends.py` — `SESSION_ISOLATION` (default `true`): each MCP session gets its own engine (documents, active document, undo, transactions); `SESSION_IDLE_TIMEOUT` releases an idle one. `preview.py` serves the read-only `/preview` page (off until `PREVIEW_PASSWORD` is set).

### FastMCP Server Structure (`server.py`)

The `mcp` FastMCP instance is configured with:
- **Lifespan** (`autocad_lifespan`): initializes the backend singleton; stores it in `ctx.lifespan_context["backend"]`
- **Middleware stack**: `ErrorHandlingMiddleware` → `AuditMiddleware` (custom timing/audit log) → `TimingMiddleware` → `LoggingMiddleware`
- **`_backend(ctx)`** helper: retrieves the backend from lifespan context, raises `ToolError` if not ready

**Tool profiles:** `TOOL_PROFILE=lean|full` (default `full`) controls the advertised surface — `lean` = 66 curated drafting tools (56 with `TOOL_PACKS=core`; `entity_modify_where` joined in 1.8-12, `layer_rename` / `layer_merge` are full-profile; which drops the three `pid_*`, the three `mech_*` and the four `arch_*` lean members, and keeps `drawing_understand` and `drawing_verify_requirements`; the five settings essentials — `drawing_apply_standard`, `dimstyle_set_current`, `textstyle_set_current`, `page_setup_apply`, `batch_plot` — are core-pack tools and stay; including `cad_batch`, since a client with a tight tool cap is exactly the client paying most per turn). **Tool packs:** `TOOL_PACKS=all|core,pid,settings,mech,arch,plant` (default `all`) advertises only the vertical packs a client uses; `core` is always on and is everything no other pack claims; `settings` is the 16 SECTION 19 environment tools, `pid` the ten P&ID tools, `mech` the 15 SECTION 20-22 mechanical tools, `arch` the 14 SECTION 24 architectural tools, `plant` the two SECTION 26 takeoffs; SECTION 17/18/23/25 are core; unknown names are ignored with a warning; a `lean` profile intersects with the enabled packs. `system_about` reports `tool_packs`.

**Tool discovery:** `DISCOVERY_MODE=off|search` (default `search` since 1.8-11; an unknown value falls back to `off` with a warning). `search` replaces the advertised catalog with `search_tools` + `call_tool` + `describe_tool` (one tool's full input schema, risk, pack, AutoCAD commands and its docstring's own examples - the synonyms stay in the search index - or up to 25 cards with `names=[...]`) plus the `DISCOVERY_PINNED` tools (default `cad_batch,drawing_info,entity_list`, listed as shortened cards: the full input schema, the first paragraph of the description; empty pins nothing), ranking hits over an AutoCAD command / synonym corpus (`discovery/aliases.py`) layered on fastmcp's BM25 index. A hidden tool stays directly callable by name. `DISCOVERY_MODE=off` restores the 1.7.0 full catalog. The plugin's `.mcp.json` sets `DISCOVERY_MODE=${AUTOCAD_MCP_DISCOVERY:-search}`.

**ISO 129 tolerances:** `dimension_linear` / `dimension_radius` / `dimension_diameter` take `tol_upper` / `tol_lower` / `tol_mode` (`symmetric` ± / `deviation` +a/-b / `limit` / `basic`) and `text_override` (e.g. `⌀20 H7`). Prefer these over hand-drawn tolerance text.

**ISO 286 fits:** the same dimension tools take `fit="H7"` (mutually exclusive with `tol_*`) — deviations are resolved from authored ISO 286 tables (`engineering/fits.py`; shafts d/e/f/g/h/js/k/m/n/p and interference r/s/t/u, holes D/E/F/G/H/JS and K/M/N/P by the ISO 286 delta rule, sizes 1–500 mm) against the measured nominal and the fit code is appended to the dimension text.

**Drawing score:** `drawing_finalize` returns `payload["score"]` — a 0-100 scalar + `invalidity_ratio` + A-F `grade` over the validator + critique union. Use it as the objective quality metric.

**Measuring:** never read vertices back and shoelace them — that loses 28.2% of the area on a semicircular edge, silently. `analysis_measure_entity(handle)` reads the real geometry, and its payload states its own accuracy: `exact`, `flatten_tolerance`, `assumed_closed`, `self_intersecting`. A HATCH reports the area it *fills* (outer loops minus islands) plus `hatch_style`; on a curved hatch edge `flatten_tolerance` is not the accuracy knob, because ezdxf hands boundaries over as cubic Beziers whose ~0.028% circle error is already baked in. `boundary_trace` / `boundary_from_entities` report the same number `analysis_measure_entity` gives for the polyline they just drew — if those ever diverge, one of them is approximating and neither says so.

**Benchmark matrix:** `benchmarks/tasks_v9.py` is the current set (49 tasks; `--matrix v8` / `v7` / `v6` / `v5` / `v4` / `v3` / `v2` reproduce the earlier sets). The task matrices stay as upstream has them, so a task only the removed live engine could run (`lisp_read_tier`, `dimension_binding`) is `environment_blocked` here, and `run_competitors --backend` accepts `ezdxf` only. The published competitor reports are pinned v1.4 runs against v2 and are **never** back-filled for later tasks — the chart shows them `not run`, not zero. A task a rival was never asked is `not_run`, a lane whose environment is absent `environment_blocked` (`run_competitors --no-fetch`), and neither enters a score; every report carries a run manifest (server SHA, dirty flag, fixture hashes, evaluator version, dependencies). `benchmarks/correctness_suite.py` (83 checks) is the release A/B gate - v1.7.0's 61, six W1, twelve W2, four W3; the published 1.8.0 report is 61 / 83 on v1.7.0 against 83 / 83, 22 fixed, 0 regressed: `python benchmarks/compare_versions.py v1.7.0 --fail-on-regression` (exit 1 on any regression; the published report is `benchmarks/results/published/ab-v1.7.0-vs-v1.8.0.json`; `scripts/check_doc_numbers.py` names it in `AB_REPORT`; a check added to the suite means regenerating that report, or the doc-numbers gate reports drift). `benchmarks/tasks_v9.py` registers v9 (v8 plus the 1.8.0 tasks) into the same `MATRICES` dict that `run_competitors` imports; `DEFAULT_MATRIX` is v9 since 1.8-25 (`EVALUATOR_VERSION` `v9.0`). The release run is `benchmarks/results/published/lanes-v9/autocad-mcp-pro.json` (47 / 47 attempted, `lisp_read_tier` `environment_blocked`, `std_tables_b40` `not_run` naming the deferred tables); 1.7.0's v8 report (`published/autocad-mcp-pro.json`) stays. In search mode the reference adapter's in-process MCP-client tasks reach every non-synthetic tool through `call_tool`, and its metadata reports `discovery_mode` and `proxied_calls`, so a search-mode pass is visibly not vacuous. A new check is a function placed just before `CHECKS` (the file ends in `main()`, so nothing after it is defined when the suite runs as a script) plus an entry at the end of `CHECKS`; it imports anything newer than v1.7.0 inside the function (compare_versions runs the new file in the old tree), and the `len(CHECKS)` pins in `tests/test_benchmark_v4..v8.py` and `tests/test_benchmark_w1_checks.py` move with it.

### Identity, operations, previews and verification (1.7), durability and errors (1.8)

**Document identity and revision.** Every open document has a `document_id` (uuid4, kept across our own `SaveAs`) and a content `revision` (`document_identity()`; reported by `system_status`, `drawing_info`, `document_list`). The revision moves wherever `dirty` is set — every mutation, undo, redo, rollback, snapshot restore — and never on a save, export, finalize or delivery.

**Operations.** `backends/operations.py` keeps one record per call (operation id, tool, request hash, state, document id, revision before/after, error kind; states `committed` / `partial` / `failed` / `refused` / `quarantined` / `cancelled` / `unknown_commit`). `AuditMiddleware` mints the id into `CURRENT_OPERATION`; `cad_batch` mints one per step. A client id (`cad_batch(operation_id=)`, `_meta.operation_id`) replays the recorded result for the same request hash, refuses `operation_conflict` for another and `requires_reconcile` after an `unknown_commit`. Since 1.8.0 (B13) the lifespan opens `backends/journal_store.py`'s `DurableJournal` (same API): every record is written through to `<ACADMCP_STATE_DIR>/journal.sqlite3` (sqlite WAL, `synchronous=NORMAL`, `busy_timeout=5000`; default folder `%LOCALAPPDATA%\autocad-mcp-pro\state`, `$XDG_STATE_HOME/autocad-mcp-pro` elsewhere), so a client id replays across restarts; a mutating call pays one commit (its `running` row, committed before it runs), its final state is flushed in the background, and at open a `running` row whose owner (pid + process start time) is dead becomes `unknown_commit` with `error_kind: "process_exit"` (a read-only tool's: `cancelled`). `JOURNAL_ARGS` (`bounded` / `digest` / `off`), `JOURNAL_SYNC`, `JOURNAL_RETAIN_DAYS`, `JOURNAL_RESULT_MAX_KB` tune it; `JOURNAL_DURABLE=off` restores the in-memory journal. A state folder inside any git checkout (this one included) or beside drawings is refused, and any store failure degrades to memory (`system_status.state_store.degraded`) - never a failed call. Tests get a private `ACADMCP_STATE_DIR` from `tests/conftest.py`; a subprocess test passes its own. Every refusal and step error carries `operation_id`.

**Previews.** `engineering/changes/preview.py`: a dry run of `cad_batch` / `drawing_refine` / `text_find_replace` / `pid_from_spec` returns an exact `preview` (entity and region fingerprints: sha256 of the exported DXF tags, read the same way at preview and apply); an apply with `expected_revision` / `preconditions` runs only if nothing moved, else it is refused `stale_revision` with nothing changed, and it reports `revision` {checked, after, interleaved}.

**Verification** (`engineering/verification/`): `requirements.py` parses typed items (refusing by path), `observe.py` builds the observed geometry (INSERTs exploded with `block_path`, MINSERT cells, HATCH loops, DIMENSION fields), `binding.py` binds by handle / feature tag / arch element / predicate / DIMENSION — two equal candidates are `ambiguous` with both, never a pick — `measure.py` evaluates from CAD-read geometry only, `report.py` writes one row per requirement with denominators that add up, and `artifact.py` re-binds and re-measures on a saved file read fresh. Rules: a requirement is never measured on a dimension's text, a stored model or typed numbers; unbound or unmeasured is `unknown`, never a pass; a DIMENSION whose text or `DIMLFAC` disagrees with the geometry is a blocking `dimension_mismatch` finding beside the geometry row; lengths use the drawing's **declared** unit (`$INSUNITS`; an inferred unit is recorded, never applied — unlike the track-H readers); evidence is stale once the revision or an artifact's sha256 moves. The mechanical generators write an `ACADMCP_MECH` feature record on every entity in its create call (`xdata=` on `entity_create_*`): a new generator must tag its features, or binding falls back to geometry. `drawing_plan(persist_requirements=True)` stores the set as the `ACADMCP_REQUIREMENTS` XRECORD. `drawing_finalize` / `drawing_deliver` with `requirements=` block on a requirement that does not pass (`failed_acceptance`), whatever the drafting score.

**Exports never re-point.** `drawing_export_dxf` writes a copy; only `drawing_save_as` re-points the document. Delivery parity is every space and every block definition against a fresh serialisation.

**Save protocol, lineage and recover (1.8-04).** Every DXF write (`drawing_save`, `drawing_save_as`, `drawing_export_dxf`, `document_close(save=True)`, and through them finalize / deliver and `drawing_template_save`) goes through `backends/atomic_write.py::atomic_write_dxf`: a pending marker in `<STATE_DIR>/pending`, `<target>.acadmcp-<pid>.tmp` in the target's own folder, flush + fsync, a check (HEADER first, `EOF`, `$ACADVER`, `$HANDSEED`, the ENTITIES count), the marker completed with the expected sha256, `SAVE_BACKUP=1` -> `<name>.bak`, `os.replace` (3 × 50 ms retries, then `save_locked`). Never call `doc.saveas` on a client's file directly. A marker a dead process left is resolved at startup and by `drawing_open` of that path (`save_recovery`: `completed` / `finished` / `rolled_back` / `orphan_tmp`). Lineage (`backends/lineage.py`) lives in `<STATE_DIR>/lineage`, never in the DXF: reopening an unchanged file continues its `document_id` and `revision`; a file changed outside the server is `external_change: true`, revision + 1 and an `external_edit` journal row; the same lineage under a second path forks (`lineage_parent`); an issued revision is never issued again. A DXF that does not parse is `damaged_drawing` and its message names `recover=True`; `drawing_open(path, recover=True)` (`backends/dxf_recover.py`, `ezdxf.recover`) reports `recovered: {fixes, errors, messages[:20], entities_read}` and a new lineage with `recovered_from`, and a save onto the damaged source is `recovered_source_protected` unless `drawing_save(overwrite_source=True)`.

**Error envelope (1.8-02).** `CapabilityRefusalMiddleware` never re-raises: every exception a tool call ends in becomes `ToolResult(is_error=True)` whose structured content is `{ok: false, kind, category, retryable, hint, tool, backend, operation_id, message, ...the kind's fields}` and whose text content is byte-for-byte the 1.7 wire text (tests pin it). `engineering/errors.py` owns the closed `ERROR_KINDS` (the 1.7 batch kinds, then `not_found`, `unknown_handle`, `path_refused`, `policy_refused`, `file_not_found`, `internal`, `requires_reconcile`, the gate kinds `validation_failed` / `critique_gate_failed` / `failed_acceptance`, the 1.8-04 `FILE_KINDS` `damaged_drawing` / `recover_unsupported` / `recovered_source_protected` / `save_locked` / `save_verify_failed` / `save_failed` / `dwg_conversion_failed`, the journal's `process_exit`, and the revise, routing and checkpoint kinds), the eight categories (`input`, `spec`, `geometry`, `file`, `policy`, `validation`, `dependency`, `internal`), one hint per kind, and `classify(exc)` - by exception type along the `__cause__` chain, never by message text. The direct route and a `cad_batch` step both call `classify`, so the routes agree on every kind (`tests/test_error_envelope.py` provokes each both ways). `retryable` is the kind's default **and** an operation record of `refused` / `cancelled` (nothing written); a retryable envelope is not stored for replay. `internal` is only for the builtin bug types (`AttributeError`, `NameError`, `UnboundLocalError`, `AssertionError`, `RecursionError`): a caller's `TypeError` / `KeyError` stays `failed`. A new refusal raises a typed exception (`EntityNotFoundError`, `PathRefusedError`, `UnknownHandleError`, `GateFailure`, …) that keeps the class its call site raised before, and a new kind is added to `ERROR_KINDS` and its table, never invented at a raise site (an undeclared kind reads as `internal`'s row); a kind whose record state is not the default is named in `server._STATE_OF_KIND` (the open / save refusals and `save_locked` are `refused`, `save_verify_failed` / `save_failed` `failed`, `process_exit` `unknown_commit`), and for the 1.8-04 kinds the envelope's message is the typed sentence (`typed_message`), not the parser's or the OS's. `AuditMiddleware`'s own refusals (`operation_conflict`, `requires_reconcile`, a malformed client id = `invalid_args`) go through `_journal_refusal`, the same envelope. A closed value checked in a tool body raises `InvalidArgsError` (a bare `ToolError` reads as `refused`). A failed finalize gate carries `{score, blocking[{code, severity, handles[:5], message}], blocking_count, qa_coverage}` (`detail="full"`: everything).

**QA reads are complete.** `engineering/qa_scan.py` takes one all-spaces snapshot per run (`readonly=True`); a check that raises is an issue with `detail.code` `check_failed`, an incomplete read `scan_incomplete` (`MAX_QA_ENTITIES`), and `drawing_refine` never repairs either. QA readers re-raise `DOCUMENT_REFUSALS` (`backends/quarantine.py`), never turn them into a finding. A new critique check reads the run's snapshot, never `entity_list(limit=...)`.

**The skill and the plugin.** The canonical premium skill is `.claude/skills/autocad-mcp-premium/` (`SKILL.md`, `references/`, `examples/`); `plugin/skills/premium/` is generated from it by `scripts/build_plugin.py` (`--check` fails on any difference — edit the canonical folder, never the copy). `plugin/.mcp.json` pins `autocad-mcp-pro[pdf,office]==<version>` (overridable with `AUTOCAD_MCP_SOURCE`), the repository-root `.claude-plugin/marketplace.json` lists the plugin, and `plugin/evals/` holds the `claude plugin eval` cases (run them only with `--no-publish` and a `--max-cost-usd`). A tool name the skill mentions must exist in `docs/tool-inventory.json` unless it sits under a "not yet" heading.

**Recipes.** `engineering/recipes/` holds versioned task recipes (`cad_batch`-shaped steps, postconditions a script checks), served as `autocad://recipes/index` / `autocad://recipes/{recipe_id}` and each run end to end in `tests/test_recipes.py`. Seven recipes since 1.8-11, among them `layer_cleanup` and `dimension_part` (the H4 and H5 jobs, one `cad_batch` each).

**Release gates.** One version in seven places (pyproject, `version.py`, `server.json`, `uv.lock`, `plugin.json`, the marketplace entry, the `.mcp.json` pin), held by `tests/test_release_consistency.py`; bump them together and run `uv lock`. CI runs `claude plugin validate --strict` (`.` and `./plugin`), the generated-file gates and `scripts/check_dist_contents.py dist` (no plugin or skill in the wheel; nothing untracked in the sdist); the release workflow adds `compare_versions.py <previous tag> --fail-on-regression`. `scripts/check_doc_numbers.py` holds the numbers README.md, `benchmarks/README.md` and CLAUDE.md quote to the code and the published reports.

### QA truth, set edits, security and measurement (1.8 W2)

**QA coverage is reported, never implied (1.8-16).** Every critique check writes `checked(focus, layout, n)` or `not_checked(focus, layout, reason)` rows into the run's `CoverageLedger` (`engineering/qa_coverage.py`, `ledger_of(shared)`; `domain_row` for a domain focus: checked, or `domain_absent`). The reasons are a closed vocabulary (`NOT_CHECKED_REASONS`: `domain_absent`, `engine_live_document_template`, `no_viewport_scale`, `viewport_scale_deferred`, `font_unresolved` - declared, no emitter before 1.8.1 - `scan_incomplete`, `check_failed`, `check_unreported`); an undeclared reason raises. `run_critique` starts a fresh ledger per run, and `_run_check` records `check_failed` for a check that raised and `check_unreported` for one that wrote no row. The five snapshot focuses write one row per layout; on a paper layout `iso128`'s legibility lane is `no_viewport_scale` (content, no model viewport) or `viewport_scale_deferred` (a viewport onto lettered model space). `drawing_critique(report=True)` returns `{issues, coverage: {layouts, complete}}`; finalize / deliver results, their gate failure and the delivery manifest carry `qa_coverage {complete, records, spaces, reason, not_checked, domain_absent}`; `strict_critique=True` fails `critique_gate_failed` on every `blocking_rows()` row - every `not_checked` but `domain_absent` - as a gate row with code `not_checked`. `summary` / `limit` on `drawing_critique`, `validation_check` and `drawing_topology_check` return `{total, by_focus, by_severity, issues[:limit]}` through `summarize` (no cursor; `total` always complete; without them the 1.7 shape). `autocad://critique/focuses` serves `engineering/critique_catalog.py::FOCUS_CATALOG`, which a test holds equal to `ALL_CRITIQUE_FOCUSES`; the `focus` parameter description names the resource instead of the enum.

**Dimension truth (1.8-15).** `engineering/dimtext.py::displayed_text(fields, style_vars)` is the one formatter of what a dimension shows (DIMDEC, DIMRND - 0 means no rounding - DIMZIN, DIMDSEP, DIMPOST - without `<>` a suffix - DIMLFAC, the Ø / R prefix, DIMADEC / DIMAZIN / DIMAUNIT for angles; round-half-even like ezdxf's renderer; `style_vars=None` keeps the 1.7 text). `bind_dimension` formats with it and reports `display_rounding`: a value shown from the measurement may sit up to half its last shown unit from the geometry without being a finding, and a count prefix (`4x Ø13.5`) is not the claimed size. Snapshot DIMENSION records carry `rendered_text` (the `*D` block's plain text, read through the same `labels.plain` reader as the displayed text, so MTEXT codes are formatting), `group42` and `dim_vars`; `*D` blocks never enter `Snapshot.blocks`. The `dimension_truth` focus (after `property_override` in `ALL_CRITIQUE_FOCUSES`) reports `dim_override_disagrees`, `dim_dimlfac_scaled`, `dim_render_stale`, `dim_group42_stale`, `dim_double_prefix`, `dim_value_hidden`, `dim_unbound`; only `dim_render_stale` and `dim_group42_stale` are `repairable`, through the backend contract method `dimension_rerender(handles, force)` (not a tool; `drawing_refine`'s repair), and the refiner sends nothing with `detail.repairable == False` - an angular `*D` showing the reflex angle is `reflex_render: true`, not repairable ("redraw it in AutoCAD"). A redraw is all or nothing: a failure is `DimensionRenderError` (kind `refused`) with the style, the scale or the edit put back and the revision unmoved. `dimstyle_modify`, `entity_scale` and `entity_edit_geometry`'s DIMENSION route redraw; the other transforms and block-definition dimensions are 1.8.1.

**Set-based edits and the `changes` payload (1.8-12).** `entity_modify_where`, `layer_rename` and `layer_merge` share one grammar (`backends/set_edits.py`): wildcards are `*` and `?` only, case-insensitive; an empty `where` or `set` is `invalid_args`. The dry run is a separate read, `entity_select_where`; `expect_count` is checked in the same locked call as the write, before any layer is created. Locked-layer entities are skipped and reported (`skipped_locked`); a paper layout's overall viewport never matches. All three answer `changes: {added: [], deleted: [], counts: {added, deleted, modified, ...}, complete: true}`.

**`dimension_auto` v2 (1.8-13).** The concrete `PremiumContract.dimension_auto` keeps the 1.7 positional order (`handles, style, offset, layer`) with the v2 parameters keyword-only, and returns `DimensionAutoResult`, a list of the drawn `EntityInfo` that also carries `skipped_existing` / `omitted` / `redundant` / `dim_overlap`; the tool answers its `to_dict()` (`{ok, created, skipped_existing, omitted, ...}`). A LINE-only selection is planned exactly as 1.7; placement is rows plus a bump (no optimiser), the overall size is drawn between real feature points so a binder can bind it, and the part box is the whole selection's. `skip_existing` binds existing DIMENSIONs with `bind_dimension` (a diameter / radius on the same circle or arc, a linear one with the same defpoints and value) - it cannot match a dimension that does not bind. The DIM layer is ensured with `_ensure_layer` before the first dimension (a dry run ensures nothing), and a 1.8-06 feature tag on a source becomes the dimension's `role: "dim"` record. It draws through the `dimension_*` methods.

**Tool policy, write paths and the HTTP guard (1.8-17).** `policy.py::refusal(tool, cost)` is one rule checked at four points: the profile visibility transform (a refused tool is not advertised; a read-only token's `tools/list` is filtered per request in `AuditMiddleware.on_list_tools`), `AuditMiddleware` before the operation record (on `_effective_tool`, so `call_tool`'s target; a hidden tool is still refused by name, `policy_refused`), `cad_batch` at plan time for every step (`cad_batch` itself is judged per step, `policy.PER_STEP_TOOLS`; one refused step refuses the batch), and `security.validate_path(allow_write=True)` (a file write is `mutate`, whatever the tool's label). A registered tool with no cost card is judged `escape`. The discovery proxies are never refused themselves. The ceiling is `READ_ONLY` → `read`, else `MAX_TOOL_COST`, lowered per request to `read` by a `MCP_AUTH_TOKEN_READONLY` token (`policy.REQUEST_CEILING`). `validate_path(path, *, allow_write=False, kinds=None)`: a writer passes its extension set (`security.KINDS_*`) or `security.DIRECTORY`, and the loadable names (`*.lsp`, `.fas`, `.vlx`, `.mnl`, `.scr`, `.arx`, `.dbx`, `.dll`, `.exe`, `.bat`, `.cmd`, `.ps1`, `.vbs`, `.js`, `acad.pgp`; trailing dots / spaces stripped, `:` refused) are refused unconditionally as `PathRefusedError` with `details.reason`. The HTTP guard is `http_guard.HttpGuard` (Origin 403, Host 421, body 413, duplicate header 400; refusal bodies `{ok: false, error, message}`, not tool envelopes), prepended by the instance wrap of `mcp.http_app` beside the `run_async` wrap, which records the bind (`http_guard.set_bind`); never rely on fastmcp's own host / origin guard (off by default, absent from SSE). `ConstantTimeTokenVerifier` compares a presented token with every configured one. A non-loopback bind also needs `ALLOWED_PATHS`.

**Session metrics and the token / call budgets (1.8-14).** `system_status(metrics=True)` is the `get_metrics` equivalent: `AuditMiddleware.on_call_tool` counts every top-level call per connection (`backends/session_metrics.py`, keyed by fastmcp's `session_id`, in memory, 64 connections and 2,048 latencies; `by_tool` records the effective tool, so the name inside `call_tool`). `benchmarks/token_budget.json` holds the 1.8.0 ceilings, each with a gate (`ci` = every PR, `release` = `--release`) and an owner; `python -m benchmarks.token_suite --budget benchmarks/token_budget.json` also fails an idle row grown more than 5 % over `benchmarks/results/published/token-cost.json`, and the CI job `token-budget` runs it with `python -m benchmarks.call_budget`. token_suite's idle headline is the prompt payload (`wire` beside it; report schema `token/2.0`), and its `task` lane prices `call_budget.py`'s naive and batched arms as a modelled session.

### Durability, history, discovery, revision, routing and DWG (1.8 W2 / W3)

**Durable checkpoints and undo after a restart (1.8-08).** `backends/checkpoints.py` (the store) keeps gzip-1 copies at `<ACADMCP_STATE_DIR>/docs/<lineage_id>/cp/cp-<seq>.dxf.gz`; `backends/ezdxf_checkpoints.py` decides when: at saves (the bytes `atomic_write_dxf(keep_data=True)` just wrote - no second serialisation), at `drawing_new` / `drawing_open` (S0, after the engineering bootstrap), at transaction / rollback-batch boundaries and at `checkpoint_create(label)` - never per call. `drawing_undo` restores the newest checkpoint below the current revision and reports `granularity` (`save` / `batch` / `label`) and `checkpoint`; with `EZDXF_UNDO_DEPTH` > 0 the in-memory per-call steps come first. `drawing_redo` crosses the memory / store boundary within a session; redo across a restart is not kept. `drawing_open` reports `lost_since_save {count, last_operation}`. `CHECKPOINT_KEEP` / `CHECKPOINT_BUDGET_MB` / `CHECKPOINT_MAX_DOC_MB` are enforced; an evicted row stays listed with `evicted: true` and restoring it is `checkpoint_evicted`. A checkpoint never bumps the revision. `JOURNAL_DURABLE=off` takes no checkpoints (capability `checkpoints` refused). Journal rows carry `checkpoint_before` / `checkpoint_after`.

**The atomic batch default and the literal-handle pre-check (1.8-09).** `cad_batch(on_error="auto")` is the default: a batch with a mutating step and no document switch runs as `rollback` (a document snapshot); a read-only batch, one with its own `transaction_*` step and one that switches documents run as `stop` and open no checkpoint; `atomicity.default_applied` says which. `engineering/changes/precheck.py` reads every literal handle of `cad_batch`, `entity_delete_many` and `entity_batch_modify` with one `entity_fingerprints` call before anything runs: a missing one is `UnknownHandleError` (kind `unknown_handle`, `missing`, nothing executed) under every `on_error`. A literal handle after a step that opens, closes, switches or restores a document (`drawing_new`, `drawing_open`, `drawing_close`, `document_activate`, `document_close`, `checkpoint_restore`, `drawing_undo`, `drawing_redo`, `transaction_rollback`) is checked when its step runs. `entity_delete_many` is all or nothing: the deletes run inside `transaction_begin`, a failure rolls the others back, and `ok` is false whenever `errors` is non-empty. `entity_batch_modify` gets the pre-check only. `entity_batch_create` and `entity_delete_many` are concrete contract methods (`EntityCreationContract`; batch types in `BATCH_CREATE_TYPES`).

**Value history and change summaries (1.8-10).** `drawing_history` reads the durable journal of the open drawing's lineage, including a restarted server's calls (reopen the file first): rows `{seq, op, tool, state, rev, cp, label, t}`; `detail="args"` adds the bounded arguments, `"changes"` each call's change summary and, for the first three rows, the checkpoint diff around it; `query` is case-insensitive over tool, label, arguments and the `ACADMCP_*` feature tokens; a label no row carries is refused `invalid_args` naming the labels there are. Labels come from `_meta.label`, `cad_batch(label=)` and `checkpoint_create(label)` (1-200 printable characters, `backends/operations.py::validate_label`). `backends/change_sets.py` gives every mutating journal row and `cad_batch` result `changes {added, deleted, counts, complete}` plus up to 20 `features` tokens: a handle-set diff per layout and named block, once per call; `modified` is 1.8.1. `drawing_diff(old_checkpoint=, new_checkpoint=)` compares checkpoints (id, seq or label; `old_path` is now optional) and every diff reports `feature` (a JSON-path diff of the `ACADMCP_MECH` / `ARCH` / `PID` payloads) and a DIMENSION's `measurement`. `system_status.operations` is `{count, last, unknown_commit}`; `system_status(detail="operations")` returns the 1.7 list of the last 20, for 1.8.0 only.

**The search default, the pins and the instructions (1.8-11).** See *Tool discovery* above. `discovery/serialize.py` builds a pin's shortened card (the registered tool, its full-catalog listing and `describe_tool` keep the untouched text). `discovery/instructions.py` builds the server instructions per surface through `server._server_instructions(mode, profile, packs)`: at most 250 tokens, batching first, naming only tools the surface advertises (`tests/test_server_instructions.py`). The skill's "Call budget" section and the plugin eval cases `layer-cleanup-budget`, `dimension-budget` and `history-round2` (written, not yet run with a real model) teach the same economy.

**Parametric revision, model history and drift (1.8-19).** `mech_part_revise(part_id, changes, overwrite=False, dry_run=False, expected_revision=None, preconditions=None, verify=True)` (`engineering/mech/revise.py`, through generic contract members only) changes the stored model by path and rebuilds the views in one transaction: tagged LINE / CIRCLE / ARC keep their handles (`entity_edit_geometry`), a changed LWPOLYLINE / TEXT / HATCH is redrawn and listed in `handle_map`, dimensions are placed again (their handles change). Before anything is written every tagged entity is compared with the model (`engineering/mech/drift.py`): a hand edit refuses `hand_edited_tagged_entity` (category `geometry`), a part drawn before 1.8.0 (no `gen` stamp) or whose views the engine no longer reproduces `model_drift` (category `spec`); `overwrite=True` replaces both with the model. A detail view or two views sharing a view tag is refused by name. A revision is `mech_part_revise`, never delete-and-redraw. Each revision appends `{rev, at, operation_id, changes}` to the part's XRECORD in the `ACADMCP_MODEL_HISTORY` dictionary (`engineering/mech/history.py`, newest 200), which travels with the file; `mech_part_inspect(drift=True, history=True, param=...)` reads drift and history. The `model_drift` critique focus (mech domain) reports a part drawn before 1.8.0 as an `unstamped` info issue.

**Obstacle-aware P&ID routing (1.8-20).** `engineering/pid/router.py::route_avoiding` is pure (A* over a sparse Hanan grid, escape lines beside each stub, a frame round the sheet; a bend and a crossing of an existing P&ID line each add cost; ties broken by coordinate, so deterministic). `pid_line_draw(route="avoid", clearance=2.0, keep_out=[...], on_blocked="refuse"|"cross")` keeps `clearance` from every symbol that is not one of its ends; no route is `no_route` naming the enclosing tags, a search over its 50,000 nodes `routing_budget_exceeded` (both category `geometry`); `on_blocked="cross"` lists every box it enters in `obstacle_hits`. `pid_from_spec`'s `sheet.routing` defaults to `auto`, so no geometry moves; its dry run routes over the catalogue boxes with the same router; a per-line `avoid` inside it is refused. The `pid_line_through_symbol` focus reports a line segment inside a symbol box that is not its end.

**The multi-sheet P&ID project (1.8-21).** `pid_project(action="check"|"index", sheets=, manifest=, write=, include_current=True)` (`engineering/pid/project.py`) reads every sheet with the `pid_graph` reader on a private, pathless engine (cached by sha256) and never modifies a drawing: `check` returns `links` per LINK id (`matched` / `orphan` / `direction_mismatch` / `duplicate`), cross-sheet `duplicate_tags` and `line_continuity`; `index` merges the three lists with a `sheet` column. More than `MAX_SHEETS` (50) is refused by name; a `.dwg` sheet is refused with capability `dwg`; `write=` is the only file it writes. `autocad://pid/project/last` serves this process's last result. The write side (a project-wide tag sequence) is 1.8.1.

**The B40 pipeline and its deferral (1.8-22).** `scripts/build_standards.py` generates `engineering/mech/standards/_rows.py` from the two entries and refuses any disagreement by path, a filled table without two different named people (`TRANSCRIBED_BY` / `CHECKED_BY`) or a complete `ROW_SOURCE` (edition, table, page), an edition other than the module's `SOURCE`, and a broken physical invariant. **Every one of the eight tables is empty in 1.8.0 and deferred to 1.8.1 by name, because the licensed copies were not at hand**; `b40_between_rows_refused` proves the pipeline on a synthetic double entry (round numbers, not DIN values), and the v9 `std_tables_b40` task is `not_run`.

**Architecture decisions** live in `docs/adr/` (index `docs/adr/README.md`); an accepted record is never rewritten - its outcome is appended under a dated heading.

**`dwg_read` (K1).** The engine reads a DWG only in `drawing_open`, by converting it with the ODA File Converter (`backends/dwg_read.py`). The result carries `dwg_read {route: "odafc", seconds, dxf_version}`; a failed conversion is `dwg_conversion_failed` (category `dependency`, `attempts[{route, reason, seconds}]`), no converter the capability `dwg_read`. The opened document keeps its `.dwg` path, so save it as `.dxf` (or write a DWG with `drawing_export_dwg`).

### Adding a New Tool

1. Add the method to the matching module in `backends/contracts/` — `@abstractmethod` by default, `@capability("key", reason=...)` only if it is a real engine boundary (and then declare `key` in `EzdxfBackend.capabilities()`, or the gate fails)
2. Implement it in `EzdxfBackend` (`backends/ezdxf_backend.py`) using the `_async(func)` wrapper
3. Register the tool in `server.py` with `@mcp.tool(...)` calling `_backend(ctx).your_method(...)`
4. Use `_dc(result)` to convert dataclass returns to dicts

### Key Conventions

- **Entity handles**: hex strings (e.g. `"1A2B"`). Always returned from create/copy operations; required by all modify/query operations.
- **Coordinates**: drawing units (mm by default); angles in degrees, counter-clockwise from X axis.
  **Every coordinate in or out of a tool is WCS.** DXF stores
  CIRCLE/ARC/LWPOLYLINE/TEXT/INSERT geometry in a per-entity frame (`extrusion`);
  `backends/ocs.py` translates at the backend boundary, so OCS never reaches a
  tool. An entity in a plane tilted out of WCS XY reports `plane_normal` and omits
  the fields xy cannot express; writing an xy into such an entity is refused with
  `capability: "ocs_tilted_plane"` — use `entity_move` instead.
- **ACI colors**: 1–255 for specific colors, 256=ByLayer, 0=ByBlock.
- **Screenshot**: ezdxf renders via matplotlib (the `pdf` extra). `view_screenshot(region=[x0, y0, x1, y1], max_px=1568)` and `view_zoom_and_screenshot(..., max_px=)` draw exactly that window through `backends/region_render.py` and return the PNG plus a JSON report (`applied`, `framing`, `px` read from the IHDR, `region`, `requested_region`, `px_per_unit`). A zero-area region, `max_px` outside 64-4096 and a partial zoom window are refused by name.
- **`_dc(obj)`**: converts dataclasses to dicts recursively for JSON serialization.
- **Engineering layer scaffold**: `drawing_new` auto-bootstraps standard linetypes (CENTER, HIDDEN, PHANTOM) and engineering layers (GEOMETRY, DIM, CENTER, HIDDEN, PHANTOM, HATCH, TEXT, TITLEBLOCK). Pass `bootstrap=False` to opt out.
- **Generic contracts added in 1.6:** `block_define(name, entities, attdefs)` (typed primitives + ATTDEFs; `overwrite` replaces contents so INSERTs keep the name) and `entity_get/set_xdata` (typed by group code; 255-char strings, 16 KB per entity, enforced before writing).
- **P&ID reader rules:** `pid_graph` never modifies the drawing, reads geometry from the drawing (an INSERT's real rotation/scale) rather than the catalogue, and reports `source`/`confidence` per node (catalog 1.0, xdata 0.95, heuristic 0.6, inferred 0.3) — never raised by agreement between heuristics. Read `stats.confidence_min` before trusting a foreign drawing.
- **Layer states are ours, not AutoCAD's.** `layer_state_*` stores a portable snapshot in an `ACADMCP_LAYERSTATES` XRECORD; it survives save/reopen and travels with the file, and it is not listed in AutoCAD's Layer States Manager. Said in the tool docstring, in `system_capabilities.layer_states` (`mode: "xrecord"`, reason `portable_acadmcp_xrecord;not_listed_in_autocad_layer_states_manager`) and in the README.
- **Page-setup evidence is the PDF.** `batch_plot` reports `mediabox_mm` parsed from the file's `/MediaBox` (`engineering/standards/pdfinfo.py`); a page setup is verified by what a printer would get, not by the setter's return value. A style or setting write reports `changed` — re-setting a value to itself is not a change.
- **Nothing interprets coordinates in UCS.** `ucs_set` / `ucs_restore` store and activate a UCS for the operator's benefit; every tool input and output stays WCS (the repository rule above).
- **The part model, not primitives**: a machine part is `mech_part_draw` with a segment list or an outline plus typed features — never hand-drawn lines. The same rule as gears and keyways, for the same reason. A change to a drawn part is `mech_part_revise` (1.8-19), never delete-and-redraw; a part payload drawn by 1.8.0 carries `gen` and a per-view `sha`, and one without them is refused `model_drift` unless `overwrite=True`.
- **Standards tables are transcribed, never derived**: every row under `engineering/mech/standards/` carries a `SOURCE` naming standard, edition and table, and a size outside the coverage is refused by name. A B40 feature row (1.8-22) is transcribed from the licensed copy only - never from memory or a secondary catalogue - entered twice (`data/<std>.a.json` / `.b.json`) by two different named people with its `ROW_SOURCE` {edition, table, page}; the physical invariants are sanity checks, never a source of values. `engineering/mech/standards/materials.py` states which of its rows are ISO 128-50, which are ASME Y14.2M via `acadiso.pat`, and which (concrete, wood) have no mechanical standard at all.
- **Six `mech_*` critique focuses** (`mech_missing_centreline`, `mech_unhatched_section`, `mech_view_misaligned`, `mech_duplicate_dimension`, `mech_thread_unrepresented`, `mech_bom_balloon_mismatch`) run under `focus=None` and inside `drawing_finalize`; they return nothing on a drawing with no `ACADMCP_MECH` payload. A seventh mech-domain focus, `model_drift` (1.8-19, after `mech_bom_balloon_mismatch`), is silent without a part anchor and reports a part drawn before 1.8.0 as an `unstamped` info issue. `mech_view_misaligned` checks the projection axis and not the quadrant, and `mech_duplicate_dimension` catches two dimensions in the same place rather than a semantic restatement — both narrowings are in the module docstring, because the payload carries no projection angle and no engine exposes what a dimension measured.
- **Draw paths ensure their layers first.** Every mechanical/annotation draw path ensures its target layers before the first entity (ezdxf would create a missing layer silently, AutoCAD's own API would not); a new path must do the same.
- **A diameter's text stands beyond the FIRST chord point** (the AutoCAD `AddDimDiametric` rule, measured); `dimension_diameter(x1, y1, x2, y2)` annotates on the `(x1, y1)` side.
- **The plan model, not lines**: a wall is `arch_wall` (an axis, a thickness, a justification, a material) and a door or window is hosted in it by `arch_opening` — never hand-drawn lines. The engine resolves the junctions and cuts the openings; what it cannot place is in `omitted`.
- **Areas are measured, never typed**: a room's area is the planar face its label point lies in, written into the label and the `room` record by `arch_room`; no tool accepts an area from its caller, and `arch_plan_from_spec` refuses a typed `area` by path.
- **Plan text follows the plot scale**: `scale` is a denominator (50 = 1:50) and a paper height `h` is drawn at `h × scale` drawing units — no annotative objects. `lang="tr"` / `lang="pl"` switch words and the decimal separator; any other language is refused with the list.
- **Three `arch_*` critique focuses** (`arch_room_unlabelled`, `arch_wall_gap` — two wall ends within 50 mm that do not join, `arch_opening_clash`) run under `focus=None` and inside `drawing_finalize`; they return nothing on a drawing with no `ACADMCP_ARCH` record.
- **Nominal, not standard**: the furniture and sanitary blocks carry nominal catalogue dimensions and say so; the stair tool reports the Blondel relation (2R + G within 600–650 mm) as a design rule, never as a building code; the `arch` layer colours are a repository convention (ISO 13567 fixes names, not colours).
- **Read-only by default (track H)**: `drawing_understand`, `drawing_scale_check`, `drawing_topology_check` and both takeoffs never modify the drawing; `drawing_diff` writes only with `markup=True`, and a takeoff writes a workbook file, never the drawing.
- **Lengths come from the inferred unit**: a reader measures in the unit the geometry implies (text heights, wall and door sizes, overall size) and reports metres; a disagreement with `INSUNITS` is a warning with the numbers — a layout declaring inches over millimetre geometry is measured in millimetres, never ×25.4.
- **Scale check before a P&ID length**: a P&ID is a length source only when `drawing_scale_check` calls it `to_scale`; otherwise a run's length is the orthogonal estimate on the layout and the drawn length stays a comparison column (`length_source="pid"` on a schematic P&ID is refused unless `force=True`, quoting the statistics).
- **Nothing is invented (track H)**: a power the P&ID does not state stays empty and becomes an open item, an unreadable size stays `unassigned`, and no cable-section table is authored — a section comes only from the caller's `section_rules`.
- **Client drawings never enter the repository**: every track-H fixture is the synthetic plant pair (`tests/fixtures/plant_pair.py`), whose truth is computed from the positions it placed; `scripts/field_test_takeoff.py` refuses an output folder inside the repository and prints no quantity unless `--show` is given.
- **Production drawings**: For real engineering output, use the `engineering/` package primitives via the `gear_*` / `keyway_*` / `titleblock_*` MCP tools — do NOT hand-draw teeth/keyways/sections with raw `entity_create_*` calls. Always end with `drawing_finalize` for the 8-step validator.
- **A new critique focus writes coverage (1.8-16):** at least one ledger row per run (`ledger_of(shared).checked` / `not_checked`, or `domain_row` for a domain focus) and a row in `engineering/critique_catalog.py::FOCUS_CATALOG`; without them `tests/test_qa_coverage.py` fails and the run records `check_unreported`, which strict mode blocks. A new `not_checked` reason is declared in `NOT_CHECKED_REASONS` (and, if it must not block, in `GATE_EXEMPT_REASONS`) - never invented at the call site.
- **A writer passes `kinds=` (1.8-17):** every `validate_path(..., allow_write=True)` call names its extensions (`security.KINDS_*`) or `security.DIRECTORY`; `tests/test_write_path_policy.py` fails a write call site without it. A writer never needs its own autoload check - `validate_path` refuses the loadable names unconditionally.
- **Policy is a cost card, not a code path:** a new tool's `@cad_tool(cost=...)` is what `READ_ONLY` / `MAX_TOOL_COST` judge it by (a tool without one is `escape`); label a file writer by what it does to the drawing - the write itself is always `mutate`.
- **The `@cad_tool` card is `{summary, cost}` (1.8-14):** never put alias lists back on it; `acad` / `synonyms` come from `discovery/aliases.py` through `describe_tool` and `docs/tool-inventory.json` (schema 2).
- **A test that reads the whole catalog takes the `full_catalog` fixture (1.8-11):** the default is search mode, so `list_tools` shows six tools; `tests/conftest.py::full_catalog` sets `DISCOVERY_MODE=off` for that test on both imported server modules.
- **A new tool docstring stays short on the wire:** it is paid on every turn of a full-catalog client and held by `benchmarks/token_budget.json`'s `idle` ceilings; the token pass documents the mechanism that trims it.
- **A budget cell moves with its measurement (1.8-14):** a ceiling in `benchmarks/token_budget.json` is changed only together with the measurement that justifies it, by the item that owns the cell; a new least-call oracle goes into `benchmarks/call_budget.py`, and its cell then flips from `release` to `ci`.

### Premium Drawing Rules

These rules are non-negotiable for production engineering output.

1. **Plan before draw**: Call `drawing_plan(intent, scale, sheet)` *before* any
   `entity_create_*`. The returned PlanSpec is held by the backend and replayed
   by `drawing_critique` at finalize time.
2. **No coordinate guessing**: Never compute snap points (endpoints, midpoints,
   intersections, perpendicular feet) from memory. Use
   `point_from_snap(handle, "end"|"mid"|"center"|"quad"|"perp"|"near", ref_x, ref_y)`.
3. **Layer discipline**: All geometry on engineering layers (GEOMETRY, HIDDEN,
   CENTER, ...). Construction geometry on `CONSTRUCTION` layer (color 250,
   lightest weight); wipe with `construction_clear()` before finalize.
4. **Lineweights are ISO 128**: 0.13/0.18/0.25/0.35/0.50/0.70/1.00/1.40/2.00 mm
   only. Use `drawing_apply_iso_layers("mech"|"pid"|"iso13567")` to bootstrap
   correct lineweights per layer; never set lineweight manually outside this set.
   An entity takes its lineweight from its layer: -1 is **ByLayer**, -2 ByBlock,
   and -3 is **Default** (LWDEFAULT) - never ByLayer. Every lineweight input
   parses through `backends.base.parse_lineweight`, which also accepts the names
   `"ByLayer"` / `"ByBlock"` / `"Default"`; a layer refuses ByLayer and ByBlock
   by name. Entity rows carry `lineweight_name`.
5. **Corners must be explicit**: Two intersecting lines that should meet at a
   sharp corner must use `entity_trim` (with `keep_x/keep_y`) — leaving overshoot
   is reported as `untrimmed_corner` by `drawing_critique`. Rounded/beveled
   corners use `entity_fillet` / `entity_chamfer`.
6. **Dimensions via auto**: `dimension_auto(selector={"layer": "GEOMETRY"})`
   dimensions a whole part in one call (LINE runs as `chain`|`baseline`|
   `ordinate`, LWPOLYLINE edges per side, diameters, radii, the overall size);
   never one `dimension_*` call per feature. What it cannot dimension is listed
   in `omitted`, and a rerun draws nothing (`skip_existing`). Manual dimensions
   only for special cases (leader notes, ordinate origins).
7. **Critique-then-finalize**: `drawing_critique(focus=[...])` must return zero
   issues before `drawing_finalize`. Available focuses (closed enum): `iso128`,
   `layer_color`, `dim_overlap`, `untrimmed_corner`, `duplicate_entities`,
   `construction_left`, `property_override` (an entity on an engineering layer
   whose lineweight, colour or linetype is not ByLayer - codes
   `lineweight_not_bylayer` / `color_not_bylayer` / `linetype_not_bylayer`;
   `drawing_refine` sets them back to ByLayer), `dimension_truth` (a DIMENSION
   whose override, DIMLFAC, `*D` block, group 42, prefix or visibility
   disagrees with its geometry or style; only `dim_render_stale` /
   `dim_group42_stale` are repaired automatically, every other code is
   `manual_required`). Pass `focus=None` for all (it also runs `gdt` and the
   `pid_*` / `mech_*` / `arch_*` / `topo_*` focuses); every focus and what it
   reports is in `autocad://critique/focuses`. Zero issues is not the whole
   answer: read `qa_coverage` for the lanes that were not checked.
8. **Meta-tools over raw**: When a meta-tool exists for a workflow, use it; do
   not reimplement with low-level primitives. Same rule as the engineering-
   primitives line above.

### Standard Premium Workflow (template)

```python
1. plan = drawing_plan(intent, sheet_size="A3", scale=1.0)
2. drawing_apply_iso_layers("mech")        # or "pid", "iso13567"
3. construction_xline(...)                 # scaffolding (optional)
4. entity_create_line / circle / ...       # main geometry on engineering layers
5. entity_trim / fillet / chamfer          # close corners explicitly
6. handles = entity_select_smart({...})    # avoid handle-memorization
7. dimension_auto(selector={"layer": "GEOMETRY"})  # ISO 129 dims, one call
8. issues = drawing_critique(focus=None)   # must be []
9. construction_clear()                    # wipe scaffolding
10. drawing_finalize(save_path=..., screenshot_path=...)
```
